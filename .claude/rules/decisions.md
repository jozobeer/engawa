# 判断の経緯 (なぜそうなっているか)

- **Chrome ウェブストアには公開しない (2026-10-07 決定)。** 個人利用の「パッケージ化されていない拡張」として使う。権限の申告、プライバシーポリシー、Arc の商標まわりの対応は不要。配布するとしても zip の手渡しまで
- **GitHub では public リポジトリとして公開 (2026-10-09 決定)。** ウェブストアに出さない方針は変えない。名前は Side Arc のまま。公開前に全コミットの author / committer メールを GitHub の noreply アドレスに書き換え、以後のコミットもローカル git 設定で同じアドレスにする
- **名前は Side Arc (2026-10-07 決定)。** 候補の Archrome は Arc と Chrome の商標を 1 語に含み、読みにくさと審査リスクがあるため見送り。公開するなら「Arc」を含まない名前も検討対象
- **Chrome へ移行中。** Claude in Chrome の公式対応は Chrome / Edge だが、Arc などの Chromium 系でも Claude Code が拡張を検出して接続を設定する (2026-10-07 にドキュメントで確認)。Arc を続ける選択肢もある
- **スペース機能は入れない (2026-10-06 に一度実装して撤去)。** Chrome 拡張ではスペースごとにログイン状態 (プロファイル) を分けられず、ピンの組を切り替えるだけでは価値が薄いというユーザー判断。旧データ (`spaces` / `spacePins:*`) は `loadPinnedTabs()` がフォルダに変換して移行する。再提案しない
- **タイルの最大サイズは 56px。** 84px も試したが 4 列 68px の元の見た目に戻ってしまい、5 列 53px の方が良いと判断された
- **Today 欄はウィンドウごと、スペースなし。** Arc のスペースごとの Today は Chrome のタブグループで近づけられるが未実装
- **ピン留めタブは Chrome の固定タブにしない。** 固定タブの帯が溢れるため。お気に入りだけ固定する (設定でオフ可)
- **自動アーカイブの既定は 12 時間。** 固定・担当・表示中・音声再生中・シークレットは対象外 (storage.local は通常/シークレットで共有・永続するため、シークレットの閲覧データは記録しない)。分割表示はペア単位 (下記)。起動直後とインストール直後は猶予を数え直す (古いタブをいきなり閉じない)
- **お気に入りの短い名前は「薄いエンボス」で確定 (2026-10-07)。** 16px 太字、収まる最初の数文字だけ、アイコンの後ろ、縁に向かって透明に。濃さは一度強めてから半分に落とした値がユーザーの好み (「今いい感じ」)。常時表示ラベルをやめてホバー表示にする案も出したが、薄いエンボスで落ち着いた。濃さを変えるときは慎重に
- **ピン留めタブの × は編集モードだけ。** 通常モードのホバーで出ると一発で消えてしまい、Arc の「× はタブを閉じるだけ」と取り違えやすい
- **Arc の複数スペースの取り込みは、スペース名のフォルダにまとめる。** スペースが無い代わりに構造を残すため。1 スペースなら平らに入れる
- **名前変更はダイアログではなく、その場の入力欄 (2026-10-09 決定)。** `window.prompt` がサイドパネルで出るか確証が無く、Arc もその場で打つ。ダブルクリックは編集モードでなくても効く (Arc と同じで、1 回目のクリックでタブは切り替わる)。ピン留めタブはタイトルの位置が入力欄になり、お気に入りはタイルが小さいのでタイルの下に浮かぶ箱に打つ
- **フォルダへのドラッグ出し入れはタブの行だけ (2026-10-09 決定)。** フォルダ行は同じ階層の並べ替えのみで、ドラッグで入れ子は作らない (Arc 取り込みの入れ子は表示できる)。中へ入れるときは末尾に足し、途中には差し込まない
- **ピン留めタブの行の行き先は、Today 欄・お気に入りを先に、フォルダの出し入れ (`pinnedDropTarget`) を後に見る (2026-10-09 決定)。** フォルダの中のタブを Today 欄やお気に入りへ出せるようにするため。フォルダの出し入れを先に見ると、ポインターがセクションの外 (Today 欄) にあってもフォルダから出す判定が勝ち、Today へ移せない。Today 欄・お気に入りの判定はセクションの外では null を返すので、外に出たときだけ横取りする
- **Today 欄からピン留めタブ / お気に入りへのドラッグは、ポインターの位置に差し込む (2026-10-09 決定)。** 末尾に足すだけの案もあったが、Arc と同じく落とした位置に入れる。タブは増やさず、そのタブを担当タブにする。逆方向 (Today 欄へドラッグして解除) も入れる。解除してお気に入り / ピン留めから Today に戻したとき、担当タブがあればそれを Today の落とした位置へ動かし、無ければその位置に新しいタブを開く (項目を消さない。「お気に入りを Today へ出すと消える」不具合の修正)
- **ドラッグでの並べ替え・出し入れは編集モードを使わない (2026-10-09 決定)。** 以前は鉛筆ボタンで編集モードにしないと動かせなかったが、Arc はいつでもドラッグで動かせる。編集モードは × での削除 (と、お気に入りの追加タイルの表示) だけに残す。ドラッグの開始は × やフォルダの開閉ボタン・名前変更の入力欄の上では始めない。5px 未満の動きはこれまで通りクリック (タブ切り替え) 扱い
- **お気に入りとピン留めタブはドラッグで相互に移動できる (2026-10-09 決定)。** お気に入り → ピン留め一覧、ピン留め → お気に入りのどちらも、落とした位置に差し込む。担当タブは `transferOwnedTab` で移し替えてから元の項目を消す (消してから移すと、`removePin` と `storage.onChanged` の `pruneOrphanOwners` が同時に `releaseOwnedTab` を呼んで競合し、固定解除が抜け落ちる)。お気に入り側は固定タブにする設定に従い、ピン留め側は固定しない
- **reorder.js の pointermove / pointerup は document で受ける (2026-10-09)。** 親要素で受けると、小さい項目 (お気に入りのタイル) から速く動かしたとき最初の pointermove が親の外で起きてドラッグが始まらない。pointerdown だけ親で受け、捕捉はドラッグ開始時のまま (pointerdown で捕捉すると click が項目に届かなくなる)
- **ドラッグ中の Esc は preventDefault する (2026-10-09)。** 取り消しのために Esc を拾うが、preventDefault しないと Chrome 標準の Esc (読み込み中止) も一緒に走る。読み込みの終わらないタブが多いと、その中止処理がブラウザを数秒固める (E2E で再現した)
- **Chrome の分割表示 (split view) は Today 欄・ピン留めタブ・お気に入りに対応 (2026-10-13 決定)。** Arc は Today・ピン留め・お気に入りのどこにも分割を置けたので、お気に入りも対応した (先にピン留めタブまでを入れ、お気に入りは別 PR `feature/favorites-split` で足した)。お気に入りのタイルは 1 マスに 2 ペインを横に並べ、`pins` の要素が `{ type: "split", id, children: [{id, url, title}, {id, url, title}] }` になる (ペインに `type` は無い。`maxPins` は項目数で数えるので分割は 1)。使う API は Chrome 155 の `chrome.tabs.createSplit([a, b])` / `chrome.tabs.unsplit(splitViewId)` と `Tab.splitViewId` (manifest の変更は不要)。Chrome の分割は 2 枚固定 (Arc の 3 枚以上は不可)
- **分割のペアは Today 欄で 1 行にまとめる (2026-10-13 決定)。** Arc と同じく 1 つのまとまりに見せる。つまみは行の左端 (真ん中にしない)。Arc は 3 枚以上に分割できるので、Chrome が許すようになってもペインを足すだけで済むように。× はペインごとで、押した側だけ閉じる (Chrome の ⌘W と同じで、残りは普通のタブ)
- **分割はドラッグで作り、ドラッグで 1 枚だけ外へ出せる (2026-10-13 決定)。** 行を別の行の真ん中 (高さの中央の半分) に落とすと分割、左半分なら落とした行が左。ペインをつかむとその 1 枚だけを分割から引き出す (Arc ではできず不便だったので、ここは Arc から離れる)。ペアごと動かすのは左端のつまみ。分割を解くボタンは置かない (引き出せば解ける)。分割の帯を空けるため、まとめられる相手との入れ替えは相手の奥側 1/4 まで進んだときに行う (reorder.js の combineTarget)
- **ペアごとの並べ替えは「解く → 1 枚ずつ動かす → createSplit で作り直す」(2026-10-13)。** Chrome はペインを (ペアごとでも) `tabs.move` で動かすと分割を解き、分割を保って動かす API は無い (実機で確認)。下へは右のペインから、上へは左から動かすと 2 枚が隣り合ったまま並ぶ。固定タブと通常タブの境界をまたぐ移動は Chrome が拒むので動かさない
- **自動アーカイブと片付けは分割をペア単位で扱う (2026-10-13)。** 分割の非 active のペインは見えているのに `active: false` なので、1 枚ずつ判定すると表示中の分割の片方を閉じてしまう (修正前の不具合)。ペアの全部が対象のときだけ閉じる (`wholeSplits` / `isClearable`)
- **担当タブは分割のペインを URL 一致で奪わない (2026-10-13)。** 奪うとお気に入りの固定で分割が解け、Today 欄でも分割の片方が消える。代わりに担当タブを新しく開く。これは単独の項目の話で、分割項目は自分の 2 ペインの URL とちょうど一致する、担当の無い生きた分割のペア (`liveSplitPairFor`) だけを採用する (片方だけ一致する分割は奪わない)。reconcile (再起動後の結び直し) には `!inSplit` を足していない (既知の限界: 単独項目の URL が Today の分割ペインと同じだと、再起動時にそのペインを奪いうる)
- **⌘W で固定タブが閉じないという説明はしない。** 報告が割れていて確証が無い
- **検証はヘッドレス Chrome の E2E まで行う。** レビューは複数観点 + 反証 (Workflow) で確定した指摘だけ反映してきた。見た目の最終確認はユーザーが実機で行う
- **GitHub の PR は PR ごとに専用タブを持つ (2026-10-13 決定)。** 以前は GitHub フォルダ全体で専用タブ 1 枚 (担当 ID `"github"`) の URL を書き換えていて、PR を切り替えるたびに読み込み直しになりスムーズに見られなかった。Arc のライブフォルダは項目ごとにタブがあったので、担当 ID を `gh:<PR の URL>` にし、1 回目のクリックで開いた (または URL が一致する既存タブを採用した) タブをその PR 専用に使い回す。2 回目以降は切り替えるだけ。再クリックの挙動は従来の navigate モードのまま (そのタブを見ているときの再クリックは PR のページに戻す、サブページを別タブから切り替えたときは動かさない = `inPr`)
- **PR の担当タブは Chrome の固定タブにしない (2026-10-13)。** ピン留めタブの一覧と同じ扱い。PR ごとに固定すると固定タブの帯が溢れる。`allOwnerTargets()` の `list: true` で「固定タブにしない担当先」を判定する (`pinOwnedTabs`、`applyPinnedSetting`、`reconcileOwnedTabs` の mustBePinned、background.js の `reconcileOwnedTabsIfWiped`)
- **PR の担当先は「一覧に見えている PR」だけ (2026-10-13)。** 専用タブの設定がオン・トークンあり・フォルダの表示 (showMine / showReviews) がオンのものを `ghPrTargets()` が返す。マージ・クローズ・レビュー依頼の取り消しなどで一覧から消えた PR の担当は `pruneOrphanOwners()` が外す (タブは閉じず、普通のタブとして Today に戻り、以後は通常の自動アーカイブの対象)。旧 `"github"` 担当は廃止する。session に残っていれば孤児として外れ、更新で session が消えた場合は background.js の `migrateLegacyGhOwner()` が一度きりの移行で、`ownedPinned.github` が真なら最後の URL (`ownedUrls.github`) と一致する固定タブ 1 枚だけを固定解除し (一致しなければ固定は触らない)、`ownedPinned.github` / `ownedUrls.github` を消す。ownedUrls の stale 掃除より前に走らせる。GraphQL の部分エラーでフィールド全体が null のときは前回の一覧を保持する (空にすると全 PR の担当が外れるため)。開いている旧専用タブが PR のページにいれば、次にその PR をクリックしたとき URL 一致で採用される
- **開いている PR の行はホバーで × を出し、そのタブだけ閉じる (2026-10-13)。** 見た目は Today の行の × と同じ。項目は残る。「開いている」印 (`.open-tab`) は、その PR の担当タブがあるとき (設定オフのときは従来の `findTabForUrl`)。⌘ / Ctrl クリックと中クリックは従来どおり別の新しいタブ
- **分割項目はペインごとに担当タブ (owner id) を持つ (2026-10-13)。** 保存形は `pinnedTabs` の `{ type: "split", id, children: [tab, tab] }` (フォルダの中にも置ける)。`split.id` は担当先ではなく、DOM のキーと並べ替えの単位にだけ使う。結合と引き出しはペイン id を保ち、`ownedTabs` に触らない (`transferOwnedTab` を使わないので、二重 `releaseOwnedTab` の競合が構造上起きない)。名前変更はペインごとで、項目単位のタイトルは持たない。`walkTabs` はペインを葉として返し (path には入れない)、背景の 2 つの walker は無改造で追従する
- **分割項目の Chrome 側の組み立ては `assembleSplit` が唯一の入口 (2026-10-13)。** 冪等 (既に分割なら何もしない。strip の左右の順は見ない)。まず固定状態とタブグループが揃わなければ組まない (ユーザーのグループと固定は触らない。通知を出す。ウィンドウをまたぐと groupId は -1 になる前提で、解く・動かすより前に判定し、ユーザーの別の分割を無駄に解かない。動かした後の再判定は安全網) → 別の分割から解く → 別ウィンドウなら寄せる → 右を左の直後へ → `createSplit`。固定の揃えは `pinned` 引数で、`null` (ピン留めタブの分割。Chrome の固定タブにしない) は触らず 2 枚の固定状態が同じときだけ組み、`true / false` (お気に入りの分割。設定「固定タブにする」に従う) は `setPanePinned` で 2 枚とも揃えてから組む (固定は分割を解くので、解く → 左から右の順に固定 / 右から左の順に外す → 組み直す)。外せるのは拡張が固定したタブ (`ownedPinned`) だけで、ユーザーが固定したタブは固定のまま。「既に同じ分割なら何もしない」は、固定状態が揃えたあとと同じときだけ (片方の固定が外れた分割は、クリックで固定を揃えて組み直す)。担当タブがユーザーのタブグループの中にいて固定していないペインは、固定するとグループから外れるので固定せず、分割にもしない (通知)。起動時には `createSplit` しない (複数パネルの競合と、ユーザーが分離した分割の勝手な復活を避ける)。再構築はクリック時と、結合・Today への落とし込みのときだけ
- **Chrome の実機で確かめたこと (2026-10-13、Chrome 155、`e2e_split_items.py` の Part 0)。** `tabs.create({ index })` の index が分割の内側だと、新しいタブは分割の後ろに置かれる (ペインの間には入らない)。設計の「作成時に相方の隣に置く」は相方が分割の外のときだけ効くので、隣接の修復 (`assembleSplit` の移動) を本線にした。ほかは設計どおり: 左から右の順に固定すると [左, 右] のまま先頭に並び `createSplit` できる、右から左の順に固定を外しても隣り合う、タブグループが違う 2 枚の `createSplit` は失敗する
- **分割項目のクリックは `openSplit` で、足りないペインだけ相方の隣に開く (2026-10-13)。** 項目の id (`split.id`) をキーに直列化する。押したペインを前面にし (つまみ / 隙間は表示中のペイン、無ければ左)、見ている最中の再クリックでは押したペインだけ登録 URL に戻す (Arc の挙動が不明なので単独項目の規則に揃えた。つまみ / 隙間では戻さない)。ユーザーが片方だけ固定したタブなどで分割にできないときは、2 枚を開いたまま前面にし、通知を出す
- **ピン留めの分割行は Today の分割行と同じ「つまみ + 2 ペイン」 (2026-10-13)。** つまみがペアごと、ペインをつかむと 1 枚だけ引き出す。結合は同じ階層の単独の行同士だけ (別フォルダ間、フォルダ行、分割行とは組めない)。Today 欄の分割行をピン留めタブへ落とすと分割項目になり (保存が先、担当の結び付けが後。逆だと他のパネルの `pruneOrphanOwners` が孤児として外す)、分割項目を Today 欄へ落とすと分割のまま Today に戻る。× と Today へ戻す操作は同じ (担当を解放し、分割は Chrome に残る)。`maxPins` 相当の件数上限はピン留めタブには無い。URL が重複する分割は 1 枚だけ入れずに全体を断る
- **`moveSplitTo` は `where: "end"` に対応する (2026-10-13)。** Today 欄の空白に落とすと基準のタブが無く、以前は何も動かなかった (単独の行は `tabs.move` の index 省略で動いていた)。ウィンドウの末尾の境目を使う
- **担当の付け替え (`tabs.onReplaced`) は直列化する (2026-10-13)。** 分割項目のペアを discard すると 2 回続けて発火し、get → set を並行させると後の書き込みが先の付け替えを上書きして担当を失う。背景は `ownedTabs` の直列化キュー (`updateOwnedTabs`) で毎回読み直して旧 ID を持つ担当を全部付け替え (冪等)、パネルも `repointOwnedTab` で同じことをする。`pruneOwnedTabs` はタブ一覧を取り直してから判定する (古い `openTabs` で新 ID を「閉じた」と落とさない)。Web Locks は採らない (SW での可用性が未検証)
- **ピン留め行に結合を足したので、単独の行の並べ替えは相手の奥側 1/4 まで進んだときに入れ替わる (2026-10-13)。** Today 欄の分割と同じ規則 (`reorder.js` の `combineTarget`)。行の真ん中は「分割にする」帯。`e2e_pinned.py` の並べ替えは、行の上端寄りに落とす形に直した
- **お気に入りの分割は 1 マスで、格子の結合は相手の中央の正方形 (2026-10-13)。** 単独のタイルを別の単独のタイルの中央 (縦横とも ±1/4) に重ねると分割項目になり (左半分なら落とした側が左)、入れ替えは相手の奥側 1/4 (縦か横のどちらか) まで進んだときだけ (`reorder.js` の `combineGrid` / `swapReachedGrid`)。斜めと縁は入れ替え側に倒す。分割タイルとは組まない。ペイン id は元のお気に入りの id のままなので、結合しても担当 (`ownedTabs`) には触らない。2 枚とも担当タブがあれば固定を揃えて組み、落とした側を表示する
- **お気に入りの分割のクリック・削除・名前変更 (2026-10-13)。** クリックは押したペインを前面に、足りないペインだけ相方の隣に開く (`openSplit` をピン留めタブと共用)。2 枚とも「固定タブにする」に従って固定し、`ownedPinned` に記録する。× は項目ごと (編集モードのみ)。削除は先に分割を解いて右から左の順に固定を外し、Today 欄に分割のまま戻す。この控え (`splitReleaseSnapshot`) は保存より前に取る (保存すると `pruneOrphanOwners` が先に担当を外して分割を解くため)。名前変更はペインごと (入力欄はタイルの下)

- **テーマは「自動 / ライト / ダーク」とアクセント色まで (2026-11-12 決定、#8)。** Arc のように背景色まで選べる案もあったが、アクセント色まで (7 色) にした。背景の印象は背景画像で変えられる。アクセント色はライトとダークで別の値を持ち、どちらでも白い文字を載せて読める濃さにする。白い文字とのコントラスト比は、既定の藍 (変更前からの値) と同じ水準 (ダークで 3:1 以上、ライトでおよそ 4:1) に揃える (オレンジは一度これを割ったので濃くした)
- **見た目の設定はその場で反映して保存する (2026-11-12)。** 他の設定は「保存して更新」で保存するが、見た目は変えた結果を見ながら選ぶものなので待たない (Arc も即時)。保存は `settings` のうち見た目のキーだけを書き換え、他の項目の未保存の入力には触れない。逆に `saveSettings` は今の `settings` を引き継いで上書きする (以前は一から作り直していて、知らないキーを消していた)。`settings` が操作のたびに書かれるので、その `onChanged` で動く処理は関係するキーが変わったときだけ動かす (background の GitHub の取り直しは見た目以外のキー、設定画面のお気に入りの上限のセレクトは上限。どちらもレビューで見つけた: 見た目を変えるたびに GraphQL を送り、未保存の上限の選択を保存済みの値に戻していた)
- **背景画像は `storage.local` の `backgroundImage` に data URL で置く (2026-11-12)。** `storage.sync` は 1 項目 8 KB で入らない。`storage.local` は 10 MB でアイコンと共有なので、1.5 MB までの画像はそのまま (GIF のアニメ・SVG・ドット絵を崩さない)、それより大きい画像は長辺 2560px の WebP (品質 0.85) に縮め、縮めても 3 MB を超える画像は断る。小さい画像も保存の前に `<img>` で読めるか確かめる (Chrome が描けない TIFF・HEIC や壊れたファイルを黙って保存しない)。縮めるときも `<img>` で読む (`createImageBitmap` は SVG の Blob を読めない)。`unlimitedStorage` 権限は足さない。設定の値は「透明度」(0% で画像そのまま、既定 60%) で、ユーザーの呼び方に合わせて不透明度ではなく透明度で持つ。大きさは「全体を覆う (既定) / 幅に合わせる / 原寸」
- **設定ボタンはパネル下端のフッタバー (2026-11-23、issue #1)。** GitHub セクションの頭にあったが、開く先は GitHub だけでなく全体の設定画面なので「GitHub の設定」と読み違えられた。Arc も設定系はサイドバー下部にある。フッタは透過 + ぼかしで中身の上にかぶせ、トーストはその上に出す。GitHub の頭には更新ボタンだけ残す
- **背景画像の拡大率は「原寸」のときだけ効く別のスライダー (2026-11-23、issue #4)。** タイル配置のタイルを拡大・縮小したいという要求。大きさの選択肢を増やす案もあったが、「全体を覆う」「幅に合わせる」はパネル基準、「原寸」は画像基準で系統が違うので、透明度と同じスライダーの別項目 (10–400%、既定 100%) にした。「原寸の N%」は繰り返しの有無に関係なく意味を持つので repeat 限定にはしない (no-repeat の拡大・縮小表示にも使える)。「原寸」以外の大きさでは意味が重なるのでスライダーを無効にする。background-size には内在サイズの割合を書けないため、保存した (縮めた後の) 画像の幅を `<img>` で測ってピクセル幅に直す。大きさを持たない SVG は幅が測れず、拡大率は効かない
